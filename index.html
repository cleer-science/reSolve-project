Abstract

Agent skills are portable packages of instructions and resources an agent consults at deployment. Self-evolving them fails in two ways today. First, skills evolved from scratch underperform human-curated ones and, on a weak model, using no skill at all. Second, an evolution-time pass records one lucky trajectory that a fresh stochastic agent often fails to reproduce at deployment. We present reSolve, a per-task, oracle-in-the-loop framework built on three components. It decouples interactive solving from a self-contained deliverable that is independently re-executed in a fresh container, a protocol we call solve-and-reproduce. It enhances the sparse reward signal with a surrogate verifier that cannot access hidden tests or reference answers. It then runs verifier-guided beam search over a solution-construction graph. Within a fixed harness, a cheap model self-evolves skills that reach 74.9% mean-of-3, +14.8 points over the 60.1% human-curated baseline, exceeding the strongest official curated-skill result (67.3%, GPT-5.5/OpenHands). We also report observed failure cases and domain-level results, including performance on the 14 Natural Science tasks, to clarify when the approach does and does not help.

Method

Evolution should certify the deliverable, not the trajectory

reSolve evolves one task-specific skill package at a time. Each round, a producer agent authors a candidate skill, the candidate is frozen and handed to a new agent in a fresh container, and the resulting files are evaluated. A full pass from the hidden grader ends the search; otherwise a blind surrogate verifier diagnoses defects and guides the next refinement. The frozen package is the sole channel between the agent that writes a skill and the agent that uses it — exactly the condition the skill must satisfy at deployment.

01 · Solve-and-reproduce

Freeze it, then prove it again

Authoring and use are separated. The producer solves the task interactively, then its conversation, tool history, and workspace are discarded. Only the frozen package — a SKILL.md plus resources and scripts — crosses into a fresh container, where a new agent must re-derive the solution from it. A pass certifies the deliverable, not the authoring trace.

02 · Blind surrogate verifier

Dense feedback without leaking the answer

The hidden grader says only pass or fail. For each candidate, a verifier that cannot see hidden tests, reference answers, or grader output writes m executable checks inferred from the task description alone. Their pass rate scores progress, and the failed-check descriptions tell the producer what to repair.

03 · Verifier-guided beam search

Compute in, luck out

Evolution is beam search over a solution-construction graph: sample initial candidates, keep the top B by surrogate score, refine each into K children, repeat for D depths. Breadth and depth become an explicit test-time-compute knob, and a keep-better rule guarantees the result never falls below the curated baseline.

Scientific RSI · follow-up

From self-evolving skills to self-evolving scientific programs

SkillsBench asks whether reSolve can evolve the package an agent consults. In follow-up work we point the same search–execute–evaluate loop at the scientific program itself: its numerical implementation, its choice of method, and the functional form of an equation. The model stays fixed (stock DeepSeek V4.1 Flash, no task-specific training); what evolves is an executable artifact, and every candidate is run and scored by an independent evaluator before it can be selected. We call this scientific recursive self-improvement: the method improves round after round against real computational feedback.

Six tasks in three families share one search, sandbox, and archive stack. Each final program is frozen on training and validation data before its held-out test split is opened.

The loop

One evolution tree, four modules

Each node of the tree is a complete program or equation hypothesis. Scientists define the problem, its constraints, and the acceptance criteria; reSolve handles candidate generation, real execution, scoring, and the choice of where to search next. Strong nodes earn more expansions, but versions that fail or temporarily regress keep their full lineage and feedback, and stay eligible as parents.

01 · Task

Define what counts

The task, its starting program, the input/output contract, and an evaluation function: error tolerance, correctness checks, runtime, or fit quality.

02 · Select

Choose a parent

Pick the next starting point from the archived tree — by independent sampling, greedy refinement, or tree search over every version so far.

03 · Mutate & evaluate

Rewrite, then run it

The model writes a full new program or hypothesis. It runs in an isolated process; a host-side evaluator it cannot see scores the result.

04 · Merge

Archive and freeze

Every version is archived with its score, including crashes and timeouts. The winner is chosen on training or validation data and frozen before the test split is loaded.

Generated programs never see reference solutions, test labels, or the evaluator. Feedback is fast — seconds to tens of seconds per evaluation — which is what lets a full evolution run finish in about a minute.

Case 1 · Accurate

Semi-infinite oscillatory integrals

Fourier-type integrals over [0, ∞) appear throughout wave physics and signal processing. When the integrand oscillates quickly and decays slowly, a general adaptive integrator can return a confident number that is simply wrong. The test split holds 72 points across four decay families with sine and cosine kernels and frequencies spanning three orders of magnitude.

Calling scipy.integrate.quad directly passes 29 of 72 points with 4.2 correct digits on average, and none of the 18 Lorentzian points. After 8 model calls (about 1.7 minutes) reSolve's program passes all 72 with 10.5 digits on average. It combines multiscale sampling, Fourier-weighted quadrature, fallbacks for anomalous inputs, and an asymptotic tail correction, and routes each input to a path by its features.

Cases 2 & 3 · Fast

Faster solvers, with correctness as a hard constraint

1D heat equation. In AlgoTune's heat-conduction task, every test case must still match the reference before speed counts. reSolve replaced repeated zero-padding and per-step memory allocation with a vectorized tridiagonal update over precomputed coefficients. All 8 test cases pass; the first measurement gives a 3.15× geometric-mean speedup, and a 5-repeat timing recheck gives a stable 2.88×.

2D Brusselator. This classic model of chemical oscillation and Turing patterns couples diffusion, nonlinear reaction, and stiffness. The starting point is already strong: SciPy's BDF stiff solver with an analytic sparse Jacobian, with reference solutions cross-checked by Radau and BDF. Across three independent runs with different initial conditions, parameters, and seeds, the frozen programs pass 12/12 test cases at 2.83×, 2.70×, and 2.73×. The fastest programs independently adopted LSODA — never mentioned in the prompt — and dispatch between LSODA and BDF by problem size, with fallbacks and vectorized differencing.

Cases 4–6 · Discover

Searching over the law itself

The first three tasks optimize how a known problem is solved. In equation discovery, the search target becomes the mathematical structure. In the two LLM-SR tasks, each candidate is an equation with free coefficients; a fixed optimizer fits them on training data, and the fit is what the next round sees.

Case 4 · Feynman geometric optics

On a relation from the Feynman Lectures (SRSD-Feynman I.27.6), variables are anonymized as x0, x1, x2; the model sees neither the equation's name nor its form. The evolved discovery program drives test NMSE from 0.49 to 2.7×10−21. A single constant-refinement step on training data — no model call — then recovers the formula exactly.

Case 5 · Nonlinear oscillator

From observations of time, position, and velocity (LLM-SR benchmark), predict acceleration. Training data cover t ∈ [30, 50]; the out-of-distribution test covers the unseen window t ∈ [0, 20], where position and velocity amplitudes reach 2.6× and 2.8× their training range. Selection uses training error only.

Search starts from a linear equation and progressively adds periodic forcing, nonlinear terms, and state coupling. At call 4 a candidate regressed to NMSE 0.18. The tree kept that branch; its child at call 5 introduced a new nonlinear damping structure and dropped training NMSE to 5.9×10−10. After 24 model calls in 87 s, the frozen equation reaches out-of-distribution NMSE 1.4×10−6 (R2 = 0.999999), about 84,000× lower than the linear start.

Case 6 · Bacterial growth

Predict E. coli growth rate from population density, substrate concentration, temperature, and pH (LLM-SR benchmark). In the run with the lowest training error, out-of-distribution NMSE falls from 1.20 to 0.025, about 48× lower.

The evolved equation contains a Monod substrate term, μBS/(K + S), the same form as the substrate term in the generating equation. For the non-standard temperature and pH responses, it fits bell-shaped approximations centred near 35 °C and pH 7.0.

From geometric optics to nonlinear dynamics to a multivariate biochemical system, only the task definition, search space, and evaluation function change. The same machinery covers program optimization, numerical-method search, and equation discovery.

Cost

About a cent per evolution run

Every experiment uses stock DeepSeek V4.1 Flash with no task-specific training or fine-tuning. Across 30 formal runs, the median run takes 75 s and about 1.1¢ of model calls. Counting everything — early exploration, controls, and failed attempts — the science work used 504 model calls and about 1.2M tokens.

One condition matters as much as the model: verification is fast. Integration accuracy, solver speed, and equation error can each be checked in seconds, so many rounds fit in a minute. Carrying this into materials, chemistry, energy, and semiconductors moves the bottleneck to physical verification — how quickly and credibly high-throughput simulation, multiphysics models, surrogates, instruments, and automated labs can close the same loop. That is the next step for this line of work.

What we learned

A skill is finished when it removes decisions from its executor

Self-evolution is refinement, not genesis.

Anchored on the curated package, the producer starts from working expert knowledge and only needs a task-specific improvement: +14.8 points. From scratch, the whole burden of exploration falls on the generator, and the result stays 30.9 points below the full framework. The benefit also scales with the model doing the evolving — Gemma 4 31B gains +5.2 where DeepSeek gains +14.8 — so evolution amplifies capability rather than substituting for it.

Reproduction pressure selects for executable code.

All 77 retained evolved packages contain at least one executable entry point; the archive holds no prose-only package. A procedure externalized as code survives re-execution with far less interpretation than guidance a fresh agent must re-derive. Consistent with this, an agent-free arm that simply invokes the saved entry point reaches 71.4%, within 3.5 points of the full system.

Remaining failures live in the executor, not the skill.

Across 258 deployment trials, the agent rarely crashes; it completes confidently and produces files the grader rejects. Failed trials are not lazy either — on 11 of 14 tasks with both a passing and a failing trace, the failing one used more tool steps. Extra actions are not free: an agent that keeps acting after the bundled solver has produced a correct artifact can overwrite it.

What makes a good skill package.

Expose an entry point that carries out the procedure rather than describing decisions the agent must make. Pin dependencies, paths, inputs, outputs, and completion criteria. Make execution idempotent and checkpointed, so a valid intermediate artifact survives later recovery attempts. Assess quality at the package boundary — a pass certified by reSolve is one that search found and a fresh agent then reproduced. That is the difference between a skill and a lucky trajectory.
